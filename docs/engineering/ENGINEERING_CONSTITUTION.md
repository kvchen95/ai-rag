# 工程宪法：失败与降级

本文件是项目级硬约束，不是建议。所有代码、评审、发布、运行时都必须遵守。

## 1. 基本原则

1. **失败不得转换为成功。**
2. **降级必须显式、带原因、可审计。**
3. **没有能力就不做，不允许猜测。**
4. **确定性模块不得调用生成模型。**
5. **不得通过放宽检索、时间、权限条件来“恢复”结果。**
6. **生产代码不得出现中文字符串字面量。**

## 2. 允许的失败出口

| 出口 | 含义 | 必须携带 |
|---|---|---|
| `FailClosed` | 停止并拒答 | 错误码、审计原因 |
| `ExplicitDegradation` | 明确降级 | 错误码、原因、用户提示、审计 |
| `TransientRetry` | 只对声明为瞬态的错误重试 | 次数上限、退避、最终错误码 |
| `HumanEscalation` | 澄清、转人工、blocked | 触发条件、候选/上下文 |

## 3. 明令禁止

- `except Exception` 后返回 `[]`、`{}`、`""`、`None`、`0`；
- `try/except/pass` 后继续成功路径；
- 缺失 metadata 时默认放行；
- 外部响应畸形时当空结果；
- 用关键词特判补语义；
- 生产代码里硬编码中文提示词、词表、单位、错误文案；
- 用 LLM 兜底确定性解析；
- 拆不出来就“保留原问”并继续；
- 零候选后去掉时间/权限条件重试；
- 没有错误码和审计字段的降级。

## 4. 类型契约

统一使用 `api/common/result.py`：

```text
Ok(value)
Fail(code, reason)
Degraded(value, code, reason, audit)
```

`None`、空集合、空字符串不能表示失败。

## 5. 变更门禁

任何 PR 必须回答：

1. 失败后返回什么？
2. 是否把失败转换成了正常结果？
3. 是否放宽了检索、时间或权限条件？
4. 错误码和审计字段是什么？
5. 故障注入测试在哪里？

## 6. 纠错闭环

```text
发现 → 隔离 → 根因 → 修复 → 防复发 → 验证 → 关闭
```

每个违规必须同时产出：

- 代码修复；
- 一个新的自动检测器；
- 一个回归测试；
- 一条 `architecture/invariants.yaml` 规则（如尚无）。

只修代码、不加检测器，不算关闭。
